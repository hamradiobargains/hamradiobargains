Your logbook deserves a permanent home

A plain-English start with Wavelog, the free logbook you run yourself. No GitHub required. Elmer walks you from zero to connected, in the right order.

Why a second home at all

The log on the Station Companion page lives in your web browser, and browsers forget: clear the wrong thing and it is gone. Wavelog keeps your contacts in a real database that you own. Once a QSO is in Wavelog it stays there, you can reach it from any computer or phone, and Wavelog itself passes your contacts on to LoTW, QRZ, eQSL and Club Log.

Step 0: try it first, free, five minutes

Wavelog's own demo lives at demo.wavelog.org. Click around. Log a fake contact. See how it feels. The demo is shared with the whole internet, so never put a real log in it. It exists so the steps below are not a leap of faith.

The one decision: where your Wavelog lives

Wavelog is a program, not a website you sign up for. It has to run on a computer somewhere. Three honest ways to do that, easiest first.

Path 1: somebody hosts it for you

The one most hams should take

Your club or national society may already run a Wavelog for members. Clubs do this: one install, many logbooks. Ask your club officers before you pay anyone anything. If they have one, skip to "Once it is running" below.

Or rent it. Hosting companies will run Wavelog for you for a few dollars a month, and ordinary web hosting works too: Wavelog needs what most hosts already offer, PHP and MySQL. No command line, no server chores. If a host's page confuses you, that is the host's fault, not yours: pick a different host.

Path 2: at home, on a computer that is already there

No new hardware is required. The PC already sitting in your shack can run Wavelog (Windows is fine), and so can a Raspberry Pi or a spare computer if you would rather keep your main machine out of it. One honest condition: the machine has to stay on. A logbook that sleeps when the laptop lid closes is not a permanent home.

On a Windows PC, the route the Wavelog team itself recommends is Docker, a free program that runs Wavelog and its database in two tidy boxes. In order:

  1. Install Docker Desktop (the Wavelog guide below links it) and start it.
  2. Make a folder for Wavelog and save the file named docker-compose.yml from Wavelog's Docker guide into it. Before anything else, change the sample database password in that file to a strong one of your own.
  3. Open a terminal in that folder and run docker compose up -d. The first run downloads what it needs, so give it a few minutes.
  4. In your browser, go to http://localhost:8086/install and follow the installer. One landmark: when it asks for the database hostname, the answer is wavelog-db, the name of the database box, not localhost.
  5. Give it its public address. A free Cloudflare Tunnel gives the machine a secure https:// address on the internet without opening your home router to the world. The Companion needs that https:// address: a logbook that only answers at a home-network address cannot hear the live site calling. One tip that saves rework: Wavelog sets itself to whatever address you call the installer with, so if the tunnel address is ready first, run the installer through it.

Straight talk: the Wavelog team itself says hosting takes "a minimum understanding" of servers and troubleshooting. If you have a club Elmer who likes this stuff, this is a fine Saturday project together. If the words "command line" make you tired, there is no shame in Path 1. That is what it is there for.

Path 3: you already run a server

Then you do not need this page. The official documentation at docs.wavelog.org has the Docker and LAMP installs, and wavelog.org is the project's front door. Welcome back when it is running: the steps below end at the Companion.

Once it is running: four steps, same for everybody

  1. Make your station location. Log in to your Wavelog and add a station location: your callsign and your grid square. Every QSO you file lands under it.
  2. Bring your old log with you. Wavelog imports ADIF files. The Companion's Export ADIF button gives you one for the log you have been keeping there. Other loggers export ADIF too.
  3. Make an API key. In Wavelog, open your user menu, then API, and create a read/write key. This key is what lets the Companion file QSOs for you. Treat it like a password.
  4. Connect the Companion. Back on the Station Companion page, the "Your Wavelog" card takes three things: your Wavelog's address, that key, and a station profile ID. Press Test the connection: it asks your Wavelog who it is and lists your station locations with their ID numbers, so you do not have to hunt for the ID. Then Save.

From then on, a QSO you log on the Companion is filed in your Wavelog in the same moment. If a send ever fails, the QSO waits in the local log, marked unsent, until you press Send unsent. Worst case is a delay, never a lost contact.

Honest limits

  • Your Wavelog needs an address that starts with https:// for the Companion to reach it from the live site. A copy that only exists on your home network answers only while you are home, and the Companion cannot file into it even then.
  • We do not run a Wavelog, and we cannot see yours, fix yours, or recover yours. It is yours in every sense. Wavelog has a backup tool: use it now and then, the way you would back up any log you care about.
  • The key you paste into the Companion is stored only in that browser on that device. It never passes through a server of ours, because there is none in the middle.
